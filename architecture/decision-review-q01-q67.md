# J-Link MCP V2：Q1–Q67 决策复核

状态：`confirmed`

用途：消除历史问答中的编号复用、后续修订和接口草案偏差。本文是决策复核记录，不是 OpenSpec 开发文档，也不表示已经开始实现。

## 1. 复核规则

- 用户后续明确修订优先于更早回答和助手建议。
- 同一编号被重复使用时，以最后被用户明确回答或由后续整体确认覆盖的版本为准。
- “接受/确认”只确认当时明确提出的边界，不自动确认之后新增的字段或范围扩张。
- 技术上仍需真机验证的事项可以成为设计基线，但不得标记为已验证能力。

状态说明：

- `最终`：产品方向已经确认。
- `最终（修订）`：早期答案或建议已被后续决定替换，表中记录的是最终版本。
- `事实/待验证`：当前事实已明确，但实现能力仍依赖实机或 ABI 验证。

| 编号 | 最终决定 | 状态与覆盖关系 |

| Q18 | HSS/变量解析要求带 DWARF 的 ELF；`.axf/.out` 内容为 ELF 时可接受。烧录支持 ELF、Intel HEX、S-record、BIN；BIN 必须给基地址；不解析 MAP。 | 最终 |
| Q19 | 目标与本机 J-Link 配置持久化并自动加载，不采用“每次 connect 全量传入、进程退出即丢弃”的早期建议。 | 最终（修订） |
| Q20 | 保留工程配置与用户配置两层及优先级：本次调用 > 用户配置 > 工程配置 > 自动发现/安全默认。DLL 路径的最终归属由 Q23 修订为工程配置；Q66 确认加入配置读写 action。 | 最终（修订） |
| Q21 | 当时的总体功能、范围和配置共同理解被确认；后续明确修订仍具有更高优先级。 | 最终（里程碑确认） |
| Q22 | 当前没有完整官方 J-Link SDK。 | 事实 |
| Q23 | 旧版 HSS 行为作为基线；允许参考公开 SDK 镜像；Rust 只声明最小动态 FFI；工程配置记录 DLL 路径、版本和哈希；集中 DLL 调用；固定时长自动停止；持续排空与尾排空；启动前做能力与连接诊断。 | 最终；ABI、帧格式和行为待验证。 |
| Q24 | 使用独立 Rust `jlink-worker` 进程承载 J-Link DLL，而不是仅在 MCP 主进程内开线程。 | 最终 |
| Q25 | F0-A 真机验证选择 J-Link 6.98a 作为 HSS 主线，8.38 和 9.70 作为兼容性副线；各 DLL 的路径、版本和哈希独立冻结，副线结果不得外推为主线能力。 | 最终（经 F0-A 实测修订） |
| Q26 | 首版必须支持结构体、嵌套结构体、固定/多维数组；最多 10 个按顶层选择项计数，帧总字节数还受 `GetCaps` 和实测能力限制。 | 最终（修订）：明确拒绝早期“只支持标量”的方案。 |
| Q27 | 溢出和丢样证据采用 `confirmed / suspected / unknown`；证据不足时不得报告“零丢样”或“无溢出”。 | 最终 |
| Q28 | 单次原始采集默认上限 512 MiB；启动前预检空间；写 `.partial` 后原子完成；故障保留部分文件和诊断；启动识别遗留采集；不自动清理。 | 最终 |
| Q29 | 目标 halted 时先尝试 resume；失败或进入 HardFault 时 reset 后再尝试；仍不能正常运行则退出并返回故障诊断。成功采集后保持实际最终状态，不恢复最初 halted，并通知发生过的恢复动作。 | 最终（修订）：覆盖早期“halted 直接拒绝”。 |
| Q30 | MCP 主进程意外退出后，Worker 继续到请求截止时间，执行 Stop、尾排空和落盘后才释放跨进程探针租约。 | 最终 |
| Q31 | HSS 只使用静态 DWARF 地址和偏移；指针只采集地址值，不逐样本解引用；动态位置返回明确错误。 | 最终 |
| Q32 | ELF/固件身份在目标连接会话首次需要时验证并缓存；连接丢失、Worker 退出、Flash 修改或关键配置变化时失效。同一有效连接内不重复验证。 | 最终（修订）：缓存生命周期以连接会话为准，不以 UI 窗口或永久配置为准。 |
| Q33 | 首版不要求 DLL 微秒时间戳模式。J-Link 6.98a 的毫秒源时间戳按 `ms × 1000` 精确归一化为公共 `timestamp_us/time_us`，同时保存 1 ms 源分辨率和跨时钟域误差，不得把单位归一化表述为微秒分辨率。 | 最终（经用户确认与 F0-A 实测修订） |
| Q34 | 采集生命周期与数据完整性分离；存在丢样或短包时仍保留可验证数据。`aborted` 部分采集必须可识别；公共手动取消随后由 Q63 删除，Q67 确认保留 `aborted`。 | 最终（修订） |
| Q35 | 首版支持 RAM/MMIO 原始地址写入。 | 最终（修订）：覆盖 Q05 中“直接地址仅普通读取”的早期边界。 |
| Q36 | 原始内存写只用于 RAM/MMIO；已知 Flash 地址必须使用 `jlink_program`，并检查地址、长度、溢出、对齐和实际写入长度。 | 最终 |
| Q37 | 同一活动探针的全部 J-Link DLL 调用由一个 Worker/gateway 统一拥有并串行执行；MCP 主进程不直接加载 DLL。 | 最终（修订）：其中“HSS 期间拒绝所有操作”的早期结论被 Q39/Q64 覆盖。 |
| Q38 | 支持位域、union 成员视图、柔性/动态长度数组的显式 count 或 slice；不推断 union 当前 active member。 | 最终 |
| Q39 | HSS 期间允许变量写和 RAM/MMIO 地址写。请求可以并发提交，但 Worker 在排空间隙串行交错执行 FFI，并记录写入与采样影响；V1 不依赖同一 J-Link 会话的 DLL 并发安全。 | 最终（修订）；真实兼容性待 9.70 实机验证。 |

## 4. Q40–Q55：MCP 与 Agent 的数据边界

| 编号 | 最终决定 | 状态与覆盖关系 |
|---|---|---|
| Q40 | MCP 保存完整原始数据并执行确定性的统计、变化检测、时间窗口、降采样和事件对齐；Agent 负责解释、诊断和下一步操作。MCP 不声称因果关系。 | 最终 |
| Q41 | HSS 完成默认返回有长度限制的高信号摘要、变量变化概况、事件索引、质量异常和 capture 标识；不自动返回全部变化。 | 最终；字段继续受 Q52/Q57 的最小化规则约束。 |
| Q42 | 精确变化是观测事实；“显著变化”只有请求提供明确阈值、范围、持续时间或次数规则时才计算。 | 最终 |
| Q43 | 普通变量/内存读取只返回本次值或字节；HSS 详细数据才使用 capture、时间窗口、有界结果和游标。普通读取超限明确拒绝，不静默截断。 | 最终（修订） |
| Q44 | HSS 对结构体和数组保留层次，只给变化成员/元素数量、索引范围和有限预览；详细变化按路径查询。 | 最终 |
| Q45 | 时间线只记录可能影响采样或目标状态的事件与质量问题；普通 status/read 查询不进入目标时间线。 | 最终 |
| Q46 | 阈值使用固定声明式规则，不支持任意表达式或脚本；同一规则格式可在 start 预设，也可对已完成采集重新查询，且永不改变原始样本。 | 最终（修订）：同编号的“规则种类”和“使用时机”合并为一个最终边界。 |
| Q47 | `jlink_hss.query` 使用 `overview / changes / window / around_event` 四种固定视图，不增加新工具，也不使用万能可选参数接口。 | 最终 |
| Q48 | 阈值路径支持确定成员与数组 `[*]`；不支持递归 `**`、任意过滤表达式或指针跟随。 | 最终 |
| Q49 | HSS start 由请求选择 `return_when: started | completed`；无论调用是否继续等待，Worker 都独立完成采集。 | 最终 |
| Q50 | `window` 必须由 Agent 显式选择 `raw` 或明确降采样模式；MCP 不静默降采样。 | 最终 |
| Q51 | 除有界查询外，提供完整自描述原始采集的 MCP 资源链接；不在普通工具结果中复制文件内容。 | 最终 |

Q65–Q67 已解决上一轮发现的全部接口偏差：

|---|---|---|
| `capture_key` 适用范围 | 所有 HSS start 必填。 | 已确认并写入接口合同。 |
| 配置公共接口 | `jlink_target` 加入 `config_get/config_set`。 | 已确认并写入接口合同。 |

当前没有待用户选择的产品或公共接口分支。J-Link 6.98a 主线的剩余 HSS 证据、8.38/9.70 副线兼容性和现代 MCP 客户端兼容性属于后续验证项，不属于未确认产品决策。

## 7. 已消除的主要冲突

- RTT：最终不进入首版。
- 接口数量：最终为 6 个领域工具，而不是约 15 个独立工具。
- 配置：最终持久化自动加载；DLL 路径、版本、哈希以工程配置为基线。
- 类型：最终支持结构体、数组、位域和 union，不限于标量。
- 原始地址：最终允许普通 RAM/MMIO 读写；Flash 必须走 program。
- halted：最终自动 resume/reset 恢复并报告，不直接拒绝。
- HSS 独占：最终允许写入交错，但不允许 DLL 并发进入。
- HSS 停止：最终没有 Agent stop/cancel。
- 返回值：普通调用最小化；HSS 才携带时间、质量、分页和资源语义。
- 曲线：完整数值曲线可获取，但 MCP 不生成图片。
