# W001 J-Link MCP V2 首版实现交接

> codex/v1-implementation 已完成并提交 P1 2.1-2.5；OpenSpec 进度 11/35，当前进入 2.6 六工具严格 MCP 合同。真机会话、halted/HardFault 恢复和 validate after 合同已通过。

## 目标

在 Windows x64 上按已确认 OpenSpec 和受控无人开发规则完成 J-Link MCP V2 的 2.1-5.5；当前完成 P1 2.6 六工具目录、严格 action Schema、最小结果、结构化错误和资源占位合同，5.6/5.7 与 JTAG 真机验证保持待办。

## 当前状态

分支 codex/v1-implementation 已以原子提交 1212cb6 完成 2.5，工作区干净，OpenSpec 为 11/35。2.5 真机证据使用 S32K144、SWD 4000 kHz、J-Link 6.98a，最终 CPU running。当前开始 2.6；用户已确认统一恢复通知为 reset_after_fault，并授权简单命名、文档一致性和机械修正直接处理。

## 已完成工作

2.1-2.5 均已按任务原子提交。2.5 实现单活动目标、首次验证缓存、connect/status/disconnect/validate、显式 ValidationAfter、halted 恢复、同一 Worker/DLL 会话真实 HardFault 注入与生产 reset/run 恢复。断开态 validate 要求 after: run | halt，活动连接拒绝 after。稳定错误码已收敛为 TARGET_CONNECT_FAILED，证据记录位于 validation/p1-ses.md。

## Bug 诊断

S32K144 的 J-Link 初始化会归一化连接前状态，因此断开态 validate 无法推断原运行意图；已通过显式 after 合同解决。提交前还发现实现曾输出合同外 TARGET_CONNECTION_FAILED/TARGET_VALIDATION_FAILED，已统一为冻结的 TARGET_CONNECT_FAILED。2.6 前审计发现公开接口单个旧示例 reset_after_resume_failure 与 OpenSpec/实现不一致，用户已确认统一为 reset_after_fault。

## 决策与约束

代码定位、实现、调试和修复仅由主窗口执行；Sol Advisor 只可用于只读审查。简单命名、文档一致性和机械修正不再询问；只有改变架构、公共能力、安全假设、验证强度或造成实际阻塞时暂停确认。硬件证据仅允许 S32K144、SWD 4000 kHz、J-Link 6.98a；不得声明 JTAG 真机支持或回退。Git 使用中文固定模板，2.7/3.7/4.8/5.5 才集中推送。

## 失败尝试

连接前 Commander 注入的 HardFault 会被器件初始化归一化；DCRDR/DCRSR 间接 PC 写入未改变 PC。已停止这些路线，改用仅测试编译的 JLINKARM_WriteReg 同会话注入并取得真实 HardFault 证据。

## 验证

2.5 已观察 workspace 全部测试、依赖方向、格式、严格 Clippy、OpenSpec strict 全部通过。T-P1-SES 真机覆盖 halted、真实 HardFault、connected validate、detached after=halt/run，目标 ID 0x2BA01477，最终 CPU running。DLL、OUT 和两个受保护 SVN 文件哈希前后不变，无残留 JLink/jlink-worker 进程。
