# W001 J-Link MCP V2 首版实现交接

> P0 已完成 F0-A/B/C 与 F0-D 协议实验；6.98a 主线真机通过但有时间戳/溢出证据限制，F0-D 仅剩目标 ChatGPT Desktop 经 Secure MCP Tunnel 的人工客户端验收。

## 目标

在 Windows x64 上实现内部个人使用的 Rust J-Link MCP V2：通过本机 stdio 为 ChatGPT Desktop 提供烧录、校验、ELF/DWARF 变量与原始内存读写、核心寄存器、目标控制，以及固定 1-300 秒 HSS 采集和确定性查询；最终以真机和目标客户端证据完成验收。

## 当前状态

P001 和分支 codex/p0-feasibility 均在进行中。F0-A 为 PASS_WITH_LIMIT，F0-B 为 PASS_WITH_LIMIT，F0-C 为 PASS；F0-D 的官方 MCP SDK stdio 自测已 PASS，但目标 Windows ChatGPT Desktop 尚未实测。OpenSpec 任务 1.2-1.4 已勾选，1.5/1.6 保持未完成；P1 禁止开始。

## 已完成工作

F0-A 使用 J-Link 6.98a、S32K144、SWD 4000 kHz 完成 10 blocks × 1 kHz × 300 秒采集、3 次交错写入、恢复原值并保持目标运行。F0-B 完成真实 Windows named pipe 重新附着、父进程退出续行、幂等 capture_key、租约和 partial 恢复。F0-C 使用 IAR 8.32.3 隔离 fixture 与实际 T26_DCU_APP_NXP.out 完成 DWARF 3/4、debug_types、15 个访问计划验证。F0-D 新增六工具 stdio mock 与官方 SDK client，自测覆盖 closed Schema、structuredContent、resource_link/read、isError、游标分页和进程重启后的 capture_key 恢复；已下载并校验官方 tunnel-client 0.0.12。

## 决策与约束

用户确认 J-Link 6.98a 为主线，8.38/9.70 为兼容性副线；不需要微秒模式，普通 J-Link 的 HSS 上限按 1 kHz 处理。主目标固定为 S32K144、SWD 4000 kHz、IAR 8.32.3 和实际 SVN 工程。用户已授权烧录、reset/resume、RAM/MMIO/变量写入、最长 300 秒采集、隔离测试固件和 Rust 工具链。SVN 既有受控修改 AppPwrMode.h 与 T26_DCU_APP_NXP.dep 不得覆盖。ChatGPT 私有 stdio 接入按 OpenAI 官方 Secure MCP Tunnel 路径，UI 自动化不得操作 ChatGPT Desktop。

## 失败尝试

J-Link 8.38/9.70 对当前探针弹出 clone warning，未作为主线；该现象不作为探针真伪的最终裁决。F0-D 首轮发现 @modelcontextprotocol/sdk 1.30.0 的 registerTool 只会向 tools/list 发布顶层 object Schema，顶层 union 虽可运行校验但不会发布 outputSchema；mock 已改为 closed object Schema 并重测通过。

## 验证

观察到 openspec validate define-jlink-mcp-v1 --strict 通过。F0-C 的 cargo fmt/test/clippy/release 与 IAR compile/link 均通过。F0-D 的 node --check、pnpm install --frozen-lockfile --offline 和 pnpm test 均通过，八项检查全部 PASS。协议证据位于 validation/evidence/f0-d/protocol-selftest.json。

## 剩余工作

用户需先确认并准备一个已关联目标 ChatGPT workspace 的 tunnel_id、runtime API key（Tunnels Read + Use）和可用 Developer mode；不要在聊天中粘贴密钥。随后用已校验的 tunnel-client 把 experiments/p0/f0d-mcp/server.mjs 作为 stdio 命令运行，由用户在目标 ChatGPT Desktop 手动创建连接并逐项执行六工具发现、structuredContent、资源、错误、分页和长任务恢复。登记独立 ChatGPT Desktop 准确包版本与交互记录，裁决 F0-D 和 P0 总门禁；只有门禁可接受后才进入 P1。

## 风险与未知

本机只检测到 OpenAI.Codex 26.818.5229.0；其 ChatGPT.exe 进程不能替代独立 ChatGPT Desktop 包身份。当前环境无 tunnel_id/runtime key，无法完成目标客户端验收。F0-A 原始 1 ms 时间戳且无独立 overflow/sequence counter；F0-B 文件租约在强制终止时可能遗留，生产实现需 kernel lease 或 PID validation。
