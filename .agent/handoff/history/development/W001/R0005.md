# W001 J-Link MCP V2 首版实现交接

> P0 已完成并裁决为 PASS_WITH_LIMIT；目标客户端已修正为 Windows Codex，F0-D 真实客户端矩阵通过，隔离探针 jlink_p0_v2_probe 已安装且旧 jlink 配置未改。P1 已获门禁许可但尚未开始。

## 目标

在 Windows x64 上实现内部个人使用的 Rust J-Link MCP V2：通过本机 stdio 为 Windows Codex 提供烧录、校验、ELF/DWARF 变量与原始内存读写、核心寄存器、目标控制，以及固定 1-300 秒 HSS 采集和确定性查询；最终以真机和目标客户端证据完成验收。

## 当前状态

P001 和分支 codex/p0-feasibility 均在进行中。P0 总裁决为 PASS_WITH_LIMIT：F0-A、F0-B、F0-D 为 PASS_WITH_LIMIT，F0-C 为 PASS。OpenSpec 任务 1.1-1.6 已完成，P1 现在允许开始但尚未执行。Windows Codex 已全局注册隔离的 P0 mock jlink_p0_v2_probe；既有 jlink server 保持启用且配置未修改。

## 已完成工作

F0-A 使用 J-Link 6.98a、S32K144、SWD 4000 kHz 完成 10 blocks × 1 kHz × 300 秒采集、300004 samples、3 次交错写入、恢复原值并保持目标运行。F0-B 完成真实 Windows named pipe 重新附着、父进程退出续行、幂等 capture_key、租约和 partial 恢复。F0-C 使用 IAR 8.32.3 隔离 fixture 与实际 T26_DCU_APP_NXP.out 完成 DWARF 3/4、debug_types、15/15 AccessPlan 验证。F0-D 的 SDK 自测和四次隔离 Windows Codex 运行验证了六工具、closed Schema、structuredContent、resource_link、结构化错误、两页游标和新进程同 key 恢复。设计、规格、任务、环境和证据文件均已把目标客户端修正为 Windows Codex。

## 决策与约束

用户确认 J-Link 6.98a 为主线，8.38/9.70 为兼容性副线；不需要微秒模式，普通 J-Link 的 HSS 上限按 1 kHz 处理。主目标固定为 S32K144、SWD 4000 kHz、IAR 8.32.3 和实际 SVN 工程。用户已授权烧录、reset/resume、RAM/MMIO/变量写入、最长 300 秒采集、隔离测试固件和 Rust 工具链。V1 唯一目标客户端为 Windows Codex，本机 stdio 直接接入，不使用 ChatGPT Desktop 或 Secure MCP Tunnel。P0 mock 必须使用 jlink_p0_v2_probe 名称，不能作为生产版本或与旧 jlink 混用。SVN 既有受控修改 AppPwrMode.h 与 T26_DCU_APP_NXP.dep 不得覆盖。

## 失败尝试

J-Link 8.38/9.70 对当前探针弹出 clone warning，未作为主线；该现象不作为探针真伪的最终裁决。早期把目标客户端误判为 ChatGPT Desktop 并规划 Secure MCP Tunnel，该路径已由用户纠正并从当前设计删除。首次用全局 Codex 配置运行客户端测试时被无关的 markitdown MCP 配置错误阻止，随后使用 --ignore-user-config 且只注入 jlink_p0_v2_probe，完成了可复现的隔离测试。

## 验证

已观察 openspec validate define-jlink-mcp-v1 --strict 通过，apply 进度为 6/35。F0-D 的 node --check 和 pnpm test 通过，八项协议检查全部 PASS；四次 Windows Codex 运行的 JSONL/final 证据已冻结。codex mcp get 确认旧 jlink 仍指向 D:\Github\jlink-mcp\out\mcp\standalone.js，P0 server 单独指向 experiments/p0/f0d-mcp/server.mjs。F0-A/F0-B/F0-C 的真机、命名管道、Rust/IAR 验证结果分别记录在 validation/f0-a.md、validation/f0-b.md、validation/f0-c.md。

## 剩余工作

收到用户明确开始 P1 的指令后，从任务 2.1 创建四 crate Rust workspace，并按 2.1-2.7 完成骨架、配置、IPC、会话和 MCP 合同；当前不要提前执行 P2-P4。生产 MCP 必须使用独立身份和路径，不得复用 P0 mock 的实现身份。P4 仍需以届时冻结的 Windows Codex 和生产 server 运行发布级端到端验收。

## 风险与未知

F0-A 原始时间戳分辨率为 1 ms 且无独立 overflow/sequence counter；实现必须如实保留质量证据。F0-B 文件租约在强制终止时可能遗留，生产实现需 kernel lease 或 PID validation。Windows Codex 在 approval_policy=never 下会阻止 destructiveHint 工具，需要正常审批流程。jlink_p0_v2_probe 当前全局启用，新窗口可见，必须继续保持 P0/非生产标识并避免与旧 jlink 混用。
