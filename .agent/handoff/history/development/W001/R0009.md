# W001 J-Link MCP V2 首版实现交接

> 正式 V1 分支已建立，P1 尚未开始。当前执行批次收敛为 OpenSpec 2.1-5.5；5.6/5.7 延后，当前不提供 JTAG。用户要求生产 Rust 与 IAR 测试代码继承 embedded-code-style 的结构极简原则并避免冗余设计。

## 目标

在 Windows x64 上实现内部个人使用的 Rust J-Link MCP V2：通过本机 stdio 为 Windows Codex 提供烧录、校验、ELF/DWARF 变量与原始内存读写、核心寄存器、目标控制，以及固定 1-300 秒 HSS 采集和确定性查询；当前先完成 OpenSpec 2.1-5.5，5.6/5.7 延后。

## 当前状态

P001 仍为 in-progress。当前分支 codex/v1-implementation 跟踪 origin/codex/v1-implementation，P1 尚未开始。用户确认当前暂不支持 JTAG，当前执行批次只覆盖 2.1-5.5；5.6 Windows Codex 端到端验收和 5.7 发布门禁保持未完成。文档已明确四 crate、单一状态所有权、同一规则只实现一次和避免只转发层，但尚未完整冻结物理目录和 embedded-code-style 的全部结构极简门禁。

## 已完成工作

P0 总门禁为 PASS_WITH_LIMIT，正式 V1 分支和 origin/main 已建立。目标工程修改、测试变量/模块、隔离测试固件和真机操作已获授权，IAR S32K144/Cortex-M4/SWD 配置为唯一依据。本轮只读对照 embedded-code-style 与 OpenSpec/architecture：确认设计已经采用少量 crate、私有 module 优先、单一写入所有者、业务规则单实现、最小结果、最小 FFI、测试证据复用和避免转发包等原则；未开始实现或运行测试。

## 决策与约束

当前阶段只实施并验证 2.1-5.5，不实施或勾选 5.6/5.7；暂不声明 JTAG 已验证。生产 Rust 应吸收 embedded-code-style 的语言无关结构原则：最小必要概念、单一写入所有者、规则复用、限制调用链、控制分支复杂度和避免无意义抽象；C 专用命名、单返回、宏对齐等不得机械套用 Rust。目标工程内新增或实质修改的 C/header 代码必须遵循目标 IAR/AUTOSAR 项目规则优先，再应用 embedded-code-style，且不做无关重排。P0 实验代码只作参考。

## 失败尝试

早期把目标客户端误判为 ChatGPT Desktop 的路径已纠正。未受控 .jlink 中 ARM7 已裁决为忽略并以 IAR 配置为准。本轮未发现已有文档完整规定 Rust 物理目录树、禁止 generic utils/helpers、内部类型默认私有或新增依赖/抽象的必要性门禁。

## 验证

本轮观察到 OpenSpec 为 35 项、已完成 6 项；代码索引只返回 experiments/p0 源码，没有生产 Rust 目录。design.md 第 33-44 行定义四 crate 和私有 module 优先，第 46-57 行定义单一状态所有权，第 59-69 行定义规则单实现、单一目的和英文 Rust 文档；tasks.md 2.1 定义格式/静态检查/英文注释门禁。未运行代码、IAR、硬件或客户端测试。

## 剩余工作

在开始 2.1 前，建议经用户确认后补强现有 OpenSpec design.md 与 tasks.md 2.1：冻结最小 workspace 物理目录；明确内部类型/模块默认私有；禁止无独立责任的 crate、manager/service/repository、utils/common 和纯转发 helper；新增 helper、依赖、状态或抽象必须有独立必要性；测试 C/header 明确应用 embedded-code-style。随后按 2.1-5.5 持续实现与分阶段验证，保持 5.6/5.7 未完成。

## 风险与未知

若直接按当前 line 69 的“复杂步骤拆为私有纯函数”执行，可能为了缩短函数而过度拆 helper；应补充只有独立语义、复用价值或明显降低复杂度时才拆分。当前文档没有精确物理目录树，2.1 实现时可能产生不同但都表面合规的层级。缺少 JTAG 不阻塞 2.1-5.5，但阻塞未来 5.7 完整发布门禁。
