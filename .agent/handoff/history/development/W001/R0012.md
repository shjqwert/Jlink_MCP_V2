# W001 J-Link MCP V2 首版实现交接

> codex/v1-implementation 已完成并推送 P1 2.1-2.7；OpenSpec 进度 13/35，当前进入 P2-3.1 镜像识别。生产 MCP 真机 connect→status→disconnect 和 P1 阶段门禁已通过。

## 目标

在 Windows x64 上按已确认 OpenSpec 和受控无人开发规则完成 J-Link MCP V2 的 2.1-5.5；当前从已通过的 P1 进入 P2 静态调试，5.6/5.7 与 JTAG 真机验证保持待办。

## 当前状态

分支 codex/v1-implementation 已推送至 3c3e4d5，OpenSpec 为 13/35，工作树干净。P1 完成四 crate 边界、领域合同、分层配置、Worker/IPC、目标会话和六工具 MCP 合同。当前开始 3.1 镜像识别与 T-P2-IMG。

## 已完成工作

2.1-2.7 均已按任务原子提交。2.6 实现六工具目录、严格 action Schema、action 级 inspect 输出校验、最小 structuredContent、公共错误映射和原始 capture 资源占位。2.7 以生产 stdio MCP 和真实 Worker 完成 S32K144/SWD 4000 kHz connect→status→disconnect，更新阶段证据并推送。

## Bug 诊断

提交前审查发现 jlink_inspect 聚合输出会拒绝合法寄存器字符串且允许空结果，已改为公开 oneOf 与运行时 action 级校验。初版 P1 smoke 未拒绝 result.isError、无条件运行 Commander 导致额外复位且未冻结 Commander 哈希；已收紧工具错误、恢复状态和可执行身份，修复后重跑真机并通过。

## 决策与约束

硬件证据仅允许 S32K144、SWD 4000 kHz、J-Link 6.98a；不得声明 JTAG 真机支持或回退。严重设计、公共能力、硬件安全或验证范围问题必须停止确认，局部机械修正自动处理。Sol Advisor 可按需审查或编码，编码时使用 max 推理强度并与主窗口串行写入；主窗口保留设计、根因、停机、硬件控制、验证、提交和推送责任。

## 失败尝试

初版 P1 smoke 在成功路径也执行 Commander 恢复，器件 InitTarget 造成一次额外 SYSRESETREQ；该证据已废弃，脚本改为仅 connect 已开始且未安全 disconnect 时才恢复，修复后输出块 d8e764 无 Commander 调用。

## 验证

最终 workspace 测试、依赖方向、格式、严格 Clippy、OpenSpec strict 全部通过；T-P1-MCP 6/6 通过。P1 真机 smoke 返回 resumed_from_halt，status 为 connected/running，disconnect 为 {}，成功路径无额外 Commander；DLL、Commander、OUT、AppPwrMode.h、T26_DCU_APP_NXP.dep 和 SVN 状态未变，无残留进程。

## 剩余工作

实现 3.1 镜像识别和 T-P2-IMG，随后按任务依次完成 3.2-3.7 烧录、DWARF AccessPlan、类型化读写、内存/寄存器/运行控制与 P2 真机阶段门禁，再继续 P3/P4 至 5.5。

## 风险与未知

P2 将直接使用 IAR 工程和真实 OUT；修改固件后旧 P0/P1 硬件行为证据只能保留 ABI 参考，相关行为必须重新验证。AppPwrMode.h 和 T26_DCU_APP_NXP.dep 是既有用户修改，不得覆盖；5.6/5.7 与 JTAG 真机仍待办。
