# W001 J-Link MCP V2 首版实现交接

> 正式 V1 分支已建立，P1 尚未开始。用户授权 2.1-5.7 期间按实际 IAR 工程修改测试代码、增加测试变量/模块并生成隔离测试固件；目标配置只以 IAR 的 S32K144/Cortex-M4/SWD 配置为准。

## 目标

在 Windows x64 上实现内部个人使用的 Rust J-Link MCP V2：通过本机 stdio 为 Windows Codex 提供烧录、校验、ELF/DWARF 变量与原始内存读写、核心寄存器、目标控制，以及固定 1-300 秒 HSS 采集和确定性查询；最终以真机和目标客户端证据完成验收。

## 当前状态

P001 仍为 in-progress。origin/main 指向 c6217289bad2d86ee763b27ea058284888df5fb0；当前分支 codex/v1-implementation 从 P0 冻结提交 282091c8a285e12be50e73a47183251894b80a88 创建并跟踪 origin/codex/v1-implementation。P1 尚未开始。2.1-5.7 的软件生产、fixture、IAR 测试固件和真机验证可以默认持续自动执行，但最终能否完全无人值守仍取决于硬件在线、客户端自动审批和 JTAG 发布证据。

## 已完成工作

P0 总门禁为 PASS_WITH_LIMIT，OpenSpec 任务 1.1-1.6 已完成并冻结。正式 V1 分支和 origin/main 已建立。本轮只读审计了 2.1-5.7 的自动化边界，并核对实际 IAR 配置：Appl\settings\T26_DCU_APP_NXP.S32K144.driver.xcl 明确 cpu=Cortex-M4、device=S32K144、drv_interface=SWD；Appl\T26_DCU_APP_NXP.ewd 同样引用 S32K144 设备与 Flash loader。未开始实现或运行测试。

## 决策与约束

用户授权正式开发期间修改 D:\SVN\DCU\T26_DCU\trunk\03_code\T26_DCU_APP_NXP 范围内为验证所需的目标工程代码，允许按实际工程创建测试变量、测试代码或模块并生成测试固件；仍须保留 AppPwrMode.h 和 T26_DCU_APP_NXP.dep 的既有用户修改，采用隔离构建与可恢复测试状态。目标设备、核心和接口只以 IAR 的 S32K144/Cortex-M4/SWD 配置及显式 V1 工程配置为准。Appl\settings\T26_DCU_APP_NXP_S32K144.jlink 是 SVN 未受控的 848-byte 生成设置文件，其中 Device="ARM7" 与 IAR 配置冲突，不作为输入、不修改也不删除。P0 实验代码只作参考，不演化为生产架构。用户确认正常 Windows Codex 升级不触发 F0-D 重验。

## 失败尝试

早期把目标客户端误判为 ChatGPT Desktop 并规划 Secure MCP Tunnel，该路径已纠正为 Windows Codex。本轮前置审计曾把未受控 .jlink 的 ARM7 值列为配置风险；用户确认未使用该文件，现已裁决为忽略该生成文件并以 IAR 配置为准。

## 验证

本轮观察到 openspec 仍为 35 项、已完成 6 项，待执行任务为 2.1-5.7。只读检查确认 T26_DCU_APP_NXP_S32K144.jlink 的 svn status 为 ?，第 27 行 Device="ARM7"；IAR driver.xcl 第 3、13、23 行分别为 Cortex-M4、S32K144、SWD，T26_DCU_APP_NXP.ewd 也引用 S32K144.ddf 和 FlashS32K144.board。未运行代码、IAR、硬件或客户端测试。

## 剩余工作

用户明确启动正式实现后，按 tasks.md 从 2.1 连续推进到 5.7，并在每阶段失败时先自动诊断和修复。开始前或最迟在任务 5.7 前仍需确认可用于 JTAG smoke 的硬件/连线；当前只有 SWD 证据。任务 5.6 优先使用隔离 Windows Codex 配置和自动审批路线，自动审批拒绝时才需要人工介入。任何实测限制若改变六工具公共能力、任何目标无法安全恢复、或硬件物理断连时必须暂停。

## 风险与未知

当前不能保证绝对全程无人值守：板卡断电、探针被其他进程占用、J-Link/IAR 模态窗口、自动审批拒绝和缺少 JTAG 硬件都可能需要人工处理。发布范围包含 SWD/JTAG，而现有 S32K144 证据只有 SWD；没有 JTAG smoke 时不得把 5.7 宣称为完整通过。F0-A 的 1 ms 源时间戳和 F0-B 租约限制仍需在生产实现显式处理。
